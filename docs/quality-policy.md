# Application qualification

Application quality runs for every pull request, main update and merge-group candidate. It has no path filters. Linux and Windows each run the locked install, all-workspace/backend/tool typecheck, lint, unit/backend tests, web/desktop production builds, native JavaScript exports and client journeys with the [per-function risk gate](function-risk.md). Each independent check runs after a successful install even if another check failed. A separate hosted Linux job runs the [core-rule mutation gate and weakened-assertion control](mutation-testing.md). A failed, cancelled or skipped matrix or mutation job cannot make `quality-gate` pass.

## Native qualification

The source-bound simulator build, four device groups, [isolated owned-modal route](native-owned-modal-route.md), pinned AX request control and [reset-settle route](reset-settle-observation.md) are required by `quality-gate`. They run the complete original gameplay and corruption/reset flows with their original assertions and 600 ms reset swipes. Since #138 they also wait up to 60 s for the first screen after each cold launch and for each preference save to settle, and the reset search has a 180000 ms/30-inspection limit (60000 ms before).

Only pull requests consisting entirely of added or modified allowlisted content skip the native build and every native job. The allowlist in [`docs-only-native.mjs`](../scripts/workflows/docs-only-native.mjs) covers root `README.md`, Markdown files under `docs/`, and these standalone marketing files: `site/pages.mjs`, `site/style.css`, `site/README.md`, `site/assets/iphone-setup.png` and `site/assets/iphone-help.png`. Site build and test scripts, machine-readable documentation, and new unlisted marketing paths require native qualification.

The workflow extracts the classifier bytes from the event base commit into a temporary module and executes that trusted policy with the PR event and diff as data. It never executes the PR working-tree classifier. Missing base policy on first adoption, invalid or unavailable base revisions, failed execution, and malformed classifier output require native qualification. The classifier checks the complete Git three-dot PR diff using event base/head revisions and verifies its file count against the event. Missing revisions or history, incomplete or malformed data, classifier errors, renames, deletions, and any mixed or unlisted change require the full native suite. Every main push and merge-group candidate runs the full suite. App, workflow, native tooling and dependency changes therefore always run native qualification, including a PR changing this classifier or workflow.

The required `quality-gate` runs with `always()` and depends on every job. It accepts skipped native jobs only when classification succeeded with an explicit content-only result and all five were skipped. Otherwise each must succeed. A failed, cancelled, missing or unexpectedly skipped device group, modal, settle or AX job cannot be bypassed by the others. A failed classification job fails the aggregate, and the native jobs default to running. Dependency audit and the device archive remain separate required checks. The archive workflow runs on every PR and main push, without path filters, so a CI-only change cannot reuse an older archive pass.

## Hosted native incident (#130)

From November 8 the device groups, owned modal and reset-settle outcomes were temporarily advisory to `quality-gate` under [issue #130](https://github.com/hemsoft-dev/yahtzee/issues/130). They still ran on every change and their failures stayed visible. The three observed hosted failure classes were reset reachability, score press touch-cancel, and launch-time intro visibility. [Main run 42336675674](https://github.com/hemsoft-dev/yahtzee/actions/runs/42336675674) and [PR run 42507150192](https://github.com/hemsoft-dev/yahtzee/actions/runs/42507150192) retain the original failures. #138 and #141 addressed the hosted-load races, launch and save waits, reset budget, driver screenshot loss and the system-gesture tap cancellation that the retained artifacts showed.

Comparison with [last-green main run 42126414160](https://github.com/hemsoft-dev/yahtzee/actions/runs/42126414160) found a mixed image rollout. Three green groups used macOS 26.6.2/image 20261026.0455.2 and green phone-6 used macOS 26.7.2/image 20261102.0473.1. The first red main run also had passing groups on both images. Xcode 26.6 build 17F113, iOS 26.5, hash-verified Maestro 2.10.0 and the iPhone 17/iPad Pro 13-inch M5 types were already selected and checked. Image movement is correlation, not a proved fix. Standard hosted image build numbers have no supported version pin.

The advisory policy ended after three consecutive green native runs on main from normal source-bound commits, none of which recorded a `systemCancelReissues` entry ([native simulator](native-simulator.md#system-gesture-cancellations)). Issue #130 lists those runs. The evidence-gated re-send remains: a re-sent tap still passes its job and stays visible as a manifest entry, job warning and step-summary line. Issues #41, #102, #112 and #115 remain open until their own criteria are met.

Run `node --test scripts/workflows/*.test.mjs` to check the classifier, real Git diff and CLI behavior, actual workflow conditions, and aggregate shell against success, failure, cancellation and unexpected skips.

Use GitHub-hosted runners for untrusted pull-request code. The persistent mini runner remains manual-only. Workflow tokens are read-only, action references are pinned, jobs have timeouts and newer updates cancel stale runs. No deployment credentials are needed.

The main branch must require the exact status `quality-gate`, require it against an up-to-date branch and require resolved conversations. Disable force pushes and deletions and apply the rule to administrators. Do not bypass a failing application check. Verify these live settings after installing the workflow; checked-in YAML alone is not enforcement.

Connected Codex current-head review is the mission's review policy. It may return a clean comment instead of formal approval. No additional human-approval count is introduced by this workflow. If maintainers add one later, it becomes a separate required gate. Administrative bypasses require an explicit incident decision and must not substitute for missing test evidence.

## Trust boundary

Executing base classifier bytes prevents a classifier edit from authorizing its own native skip. It does not protect against rewriting the PR workflow itself. A required status name is not an immutable-workflow security boundary. A pull request can edit workflow or package scripts, so a green status alone is not permission to merge. Review those edits at the exact candidate head and use the guarded merge process to check the actual workflow run, its steps and resolved review findings. Repository administrators remain trusted to manage settings; these rules do not defend against a malicious administrator.

GitHub's [required-workflow rule](https://docs.github.com/en/enterprise-cloud@latest/repositories/configuring-branches-and-merges-in-your-repository/managing-rulesets/available-rules-for-rulesets#require-workflows-to-pass-before-merging) is available at organization or enterprise level. This repository is personal-account owned. Moving ownership or provisioning a separate verifier app needs a separate owner decision; this change does not claim that unavailable guarantee or introduce privileged `pull_request_target` execution. Current-head Codex review and guarded merges remain required process controls for workflow/script changes, though branch protection itself does not enforce a Codex comment.

Record run URLs, queue time and final qualification duration when changing CI. No performance target is invented here. Keep additional mutation or soak checks tied to the exact candidate rather than treating scheduled runs of another commit as merge evidence.

Native signed iOS/Android packages are outside this build matrix. Both hosts check mobile TypeScript, Expo/Hermes exports and the mobile-source browser adapter. Desktop checks execute the real Electron main/preload and renderer, but do not prove installation or signing. See [client qualification](client-qualification.md) for the exact platform limits.
